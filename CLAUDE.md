## Git and gh in this clone

- This directory, `/mnt/rip/vicarius_drive/vicarius/modules/sponge_screener/github_repo/`, is its own git repository with the remote `laurenkolinger/vicarius-sponge-screener`. The harness monorepo above it ignores every `github_repo/` except `vicarius_llm`, so nothing committed here reaches the harness, and module code is never committed to the harness.
- Every git command is `git -C /mnt/rip/vicarius_drive/vicarius/modules/sponge_screener/github_repo ...`. The shell cwd drifts between calls on this box; a bare `git add -A && git commit` once swept 1.1M lines of unrelated harness work into a module commit.
- Verify the branch before every commit: `git -C /mnt/rip/vicarius_drive/vicarius/modules/sponge_screener/github_repo branch --show-current`. The expected branch is `main`; when it is anything else, say so and confirm before committing.
- **This repository is public.** Nothing private goes on any branch: no screening data (`data/`, sightings, frames, crops, tracks, exports), no student names or initials lists, no tokens or credentials, no host names beyond 127.0.0.1 and the public `uviai` bucket already in `screener/config.py`. The guide photos fetched by `tools/fetch_guide_images.py` are for internal use and stay in the ignored `data/guide/`.
- Stage by explicit path. Never `git add -A` and never `git add .`.
- Conventional-commit subject, a body that says why, and the closing line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- The snap-confined `gh` on this box cannot infer the repo from the cwd, so every call names `laurenkolinger/vicarius-sponge-screener` explicitly: `-R laurenkolinger/vicarius-sponge-screener` for `issue`, `pr`, `label` and `api` commands; `gh repo view laurenkolinger/vicarius-sponge-screener` and `gh repo create laurenkolinger/vicarius-sponge-screener --private` take it positionally instead, since this `gh` rejects `-R` on those two.
- Never commit data files (images, videos, checkpoints, exports, copies of NAS content). `.gitignore` in this clone lists the common patterns; data lives on the NAS and VICARIUS logs provenance.
- The pre-push hook at `.githooks/pre-push` is the logging-only shim copied from `/mnt/rip/vicarius_drive/.githooks/lib/modules-pre-push`, activated by `git -C <clone> config core.hooksPath .githooks`. It appends a row to the platform processing log on every push and never blocks. A push that produces no row means the hook install is wrong; reinstall per `/mnt/rip/vicarius_drive/vicarius/_DOCS/SOPs/GIT_SYNC_SOP.md`, section "Hooks: harness versus module repos" (line 33).

## Module requirements checklist

Each item restates a rule from the `Modules` section of `/mnt/rip/vicarius_drive/CLAUDE.md`. A module is done when every line holds.

- **Build discipline first.** Every new script, tool, page or window in this module, and every heavy revision, follows the skill `plan-build-test-iterate` (REQUIRED SUB-SKILL; installed at `/home/bizon/.claude/skills/plan-build-test-iterate/`, library copy at `/mnt/rip/vicarius_drive/vicarius/skills/plan-build-test-iterate/`): a plan that names the decisions, tests written first including adversarial cases, the existing suite green, one independent reviewer per pass, every flag fixed or reported as open, and a plain-language report. A user-interface change of any size is screenshotted at 946 and 1280 px and reviewed against `/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-09-02-workflow-page-design.md` and `/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-09-02-matrix-window-design.md` before anyone sees it. Agents are orchestrated with file ownership by default unless Lauren asks for a single pass.
- **Lock gate.** Every module is lockable. Lock state lives only in `/mnt/rip/vicarius_drive/vicarius/_METADATA/module_locks.json`, written only by `vicarius_ui_os` (`POST /api/modules/<slug>/lock` from an admin session; the session cookie is `vicarius_session`). A module that serves its own web app (`ui.launch` in `module.yaml`) copies the reference gate `/mnt/rip/vicarius_drive/vicarius/modules/reef_point_seg/github_repo/scripts/pipeline_orchestrator/lock_status.py` into its app, sets `MODULE_SLUG` to `sponge_screener`, registers a `before_request` gate on `is_locked()`, and ships a lock-gate test. Locked blocks everyone including admin; the locked page shows exactly "Under development. Please come back later. Email Lauren for questions." with a mailto to lauren.olinger@uvi.edu, and locked API calls return 423. Say "admin mode", never "dev mode".
- **Run state.** Every run lives at `inprocess/run_*/` under the module folder (the parent of this clone) and keeps a `project.json` with `id`, `name`, `created_at`, `updated_at`, `project_dir`, `repo_dir`, `current_step`, `steps` (`{n: {name, status}}`, with `status` set to `running` while a step executes), and `access_log` (a list of `{ts, initials, action, purpose}`). The VICARIUS launcher mints the folder and the stub (`/mnt/rip/vicarius_drive/vicarius_ui_os/module_views.py`, `_mint_run`); the module fills `steps` and appends to `access_log` as work proceeds, and never mints run folders through a create-project path of its own. Vesper.llm's status digests and the live snapshot read these files.
- **Signed-in initials.** Every initials field in `sponge_screener` starts on the initials the person signed in with at the VICARIUS loading page, upper-cased, and can be typed over. VICARIUS opens this module's pages with `initials=<XX>` in the URL; the page seeds its field from a valid parameter (two to four letters) first, then from what it remembered, never from a default such as LO, upper-cases the value as it is typed, and ignores an invalid parameter. The guard `/mnt/rip/vicarius_drive/vicarius_ui_os/tests/test_module_initials_seed.py` fails when a `ui.launch` module has an initials field and no page reads the parameter; the rule is in `/mnt/rip/vicarius_drive/CLAUDE.md` and the decision in `/mnt/rip/vicarius_drive/docs/adr/0010-every-initials-field-starts-on-the-signed-in-initials.md`.
- **No prompts from a UI launch.** A module with `cli.interactive: true` declares `cli.flag_map` with the keys `input_flag`, `output_flag`, `purpose_flag`, `yes_flag`, plus `skip_vim_flag` when the script opens an editor by default. The script skips every `input()` and `getpass()` when those flags are set: the UI form is the only source of inputs and the spawned terminal is for output and audit. Check this first on every module edit or migration; `vicarius doctor` warns on a violation and that warning blocks a new module. Reference: `/mnt/rip/vicarius_drive/vicarius/modules/3D_phase_1/github_repo/module.yaml` (flag_map) and its `src/run_phase1.py`.
- **A tooltip on every UI field.** Every form field, parameter, checkbox and setting in this module's UI carries one, as `title` on a keyboard-focusable `?` glyph beside the label (`i` beside a section heading). The sentence rules, in three lines:
  1. One or two complete sentences; the first names who does what. A control the user operates opens with an imperative; what the system does afterwards is a sentence with VICARIUS or the named tool as its subject.
  2. Never open with "You". No fragments, trailing negations, screen references ("above", "this tab"), or self-reference. A tooltip adds a default, a consequence, a count, or where a path points; one that only restates its label is dropped.
  3. Terms of art are explained once, on the section heading glyph; every folder or file mention says where it is or what to do with it. After writing a page of tooltips, dispatch one independent reviewer agent, on a smaller model, to classify each as keep, trim, or drop, and apply its verdicts, never the author's own. One reviewer per review ask; no panels of lenses.
- **Outputs bound to descriptors.** Every `outputs:` entry in `module.yaml` names a `dataset:` whose descriptor exists under `/mnt/rip/vicarius_drive/vicarius/_METADATA/dictionary/datasets/` (named `sponge_screener_<slug>.yaml`) with `eml: true`. On a successful run the launcher writes a `<output>.meta.json` sidecar beside each artifact whose `dataset` and `path_template` resolve, carrying a full snapshot of the descriptor plus a checksum (`vicarius/_METADATA/sidecar/generate.py`, called from `vicarius_ui_os/runner.py`). EML 2.2.0 XML is generated on demand from that sidecar, not written automatically at run end; see `vicarius/_METADATA/sidecar/README.md`. Draft a stub descriptor before merging a module that lacks one. When the module's output shape changes, bump the descriptor's `schema_version` and stamp `last_updated` on its line 3 in the same change. Viewer and launcher modules legitimately declare `outputs: []`. Rules: `/mnt/rip/vicarius_drive/vicarius/_DOCS/reference/DATA_DICTIONARY.md`.
- **Model cards.** Every module that trains a model, in any framework, writes a model card beside each weights file it produces, at the end of training, with the shared card writer at `/mnt/rip/vicarius_drive/vicarius/_METADATA/model_card/`. It fills every record field it can, asks at training time for the finding tags (subject, training data source) it cannot infer, and refreshes the card's performance part when it evaluates the model. A model without a card is not finished. Format and fields: [the VISION design, section 4](/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-10-15-vision-image-inference-design.md). The decision is in `/mnt/rip/vicarius_drive/docs/adr/0011-every-trained-model-carries-a-card-beside-its-weights.md`.
- **display_name and tags come from Lauren.** Before writing `module.yaml` ask once, tersely, for `display_name` (short, under about 20 characters) and `tags` (from 3D, AI, AUV, TCRMP, or a new one). Never fall back to the folder name.
- **Registration verified four ways.** (1) Live discovery: `cd /mnt/rip/vicarius_drive/vicarius_ui_os && .venv/bin/python -c "import module_registry as mr; print([m['name'] for m in mr.discover_modules()])"` lists `sponge_screener`. (2) `curl -s localhost:5090/api/modules | grep sponge_screener` finds it and `curl -s -o /dev/null -w '%{http_code}' localhost:5090/modules/sponge_screener` prints 200. (3) `VICARIUS_ROOT=/mnt/rip/vicarius_drive/vicarius /usr/bin/python3 /mnt/rip/vicarius_drive/vicarius/modules/update_registry.py --check` passes. (4) `module.yaml` is complete with a tooltip on every UI field. Regenerate `/mnt/rip/vicarius_drive/vicarius/modules/MODULE_REGISTRY.md` only when no other agent is mid-edit on it.
- **Glossary promotion.** `CONTEXT.md` in this clone starts as a stub whose first line is an HTML comment. When it holds real terms, delete that line and add this module to `/mnt/rip/vicarius_drive/CONTEXT-MAP.md` in the same change. Platform-wide terms stay in `/mnt/rip/vicarius_drive/CONTEXT.md`.
- **Decision records.** When a change establishes or reverses a design rule that had real alternatives, is hard to reverse, and would surprise a future reader, write `docs/adr/NNNN-<slug>.md` in this clone (format in `docs/adr/README.md`, blank form in `docs/adr/0000-template.md`) alongside the changelog entry, with a `Source:` line citing the TODO uid or the spec. Decisions that bind the platform or more than one module go to `/mnt/rip/vicarius_drive/docs/adr/` instead.

## Tests

- `/usr/bin/python3 tests/test_house_rules.py` from this clone scans every Markdown file for em and en dashes, the banned verb and its forms, and emoji, skipping backtick code spans and fenced code blocks. It prints `PASS` or the offending `file:line` list and exits 1. It runs before every commit that touches prose. A bare `python3` on this box can resolve to an unrelated project's virtual environment rather than the system interpreter, so name `/usr/bin/python3` (or this clone's own `env/bin/python` once created) explicitly rather than relying on `PATH`.
- Python suite: `env/bin/python -m pytest tests -q -m "not live and not e2e"` from the clone root (`env/` is built with `/usr/bin/python3 -m venv env` and `env/bin/pip install -r requirements.txt`). The `e2e` marker drives headless Chrome against a fake bucket and needs Node 22 or newer; the `live` marker reads the real public bucket and is run by hand only.
- Page logic: `node --test tests/test_geometry.mjs tests/test_track_math.mjs tests/test_scrub.mjs tests/test_wheel.mjs tests/test_vicarius_run.mjs`.
- `tests/test_track_worker.py` runs the tracking worker under `.venv-track/bin/python` (OpenCV and numpy) and skips with a message when that environment is missing.
- No test reaches the real bucket, port 8770 or port 5098: every server test binds port 0 with temporary data and cache folders and a fake bucket.
